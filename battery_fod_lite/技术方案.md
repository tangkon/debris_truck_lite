# 技术方案 —— battery_fod_lite（电池包上盖异物检测）

> 读者：技术负责人 / 算法工程师 / 现场集成工程师。
> 配套：《标注规范.md》（数据口径）、《部署与操作手册.md》（命令与上线）。

---

## 1. 背景与需求

换电站工况：电池包上盖在拆卸后过站，固定工业相机（1920×1080）拍一帧。
需要检测上盖表面 **≥5mm** 的异物（石子、螺栓、螺母、煤块等，统一一类 `foreign`），
业务目标召回 ≥80%（内部按"召回优先"设计，验收口径见 §10）。

部署端硬约束：

- 工控机 **2 核 CPU、≤4GB 内存、无 GPU**，且不能影响同机其它服务（节拍/优先级受限）。
- 现场只有 Python 环境（onnxruntime + opencv），不允许装 GPU 推理栈。
- 训练端有 GPU，允许 Ultralytics 全家桶。

---

## 2. 顶层决策（三条硬约束）

1. **训练尺度 = 推理尺度**。模型在什么尺度上训练，就必须在完全相同的尺度上推理。
   `export` 会把尺度链写进 `model_meta.json`（含 `grid_signature`），`detect.py` 启动时
   用本地重算的切片网格与签名逐字段比对，**不一致直接拒绝运行（exit 2）**。
   这是为了防止"静默漏检"——尺度错配不会报错，只会让 5mm 异物变成 3px 然后消失。
2. **单一实现原则**。训练端只暴露 `train.py`（prepare/train/export/eval/all 五个子命令），
   部署端只有一个 `detect.py` + 一个 ONNX。禁止第二套推理脚本上工控机。
   `detect_test.py` 是开发机全速测试端，**禁止上工控机**（它不锁核、吃满 CPU，
   数字不代表现场）。
3. **ONNX-only 部署**。FP32、静态 shape、opset 12、带 simplify。不导出 half/dynamic，
   不在 ONNX 里塞 NMS（NMS 在 detect.py 的 Python 侧做，便于按 mm 口径后处理）。

---

## 3. 总体架构（数据流）

```
原始标注（images/ + labels/，YOLO txt）
        │  train.py prepare   ← 统一类别(remap 1:0)、清洗(min-visibility)、
        │                       尺寸截断(min-mm)、切分(train/val/test)、
        │                       切片(sliced 训练集) + 全帧(eval 集)
        ▼
dataset_full（全帧，用于端到端 eval） / dataset_sliced（切片，用于训练）
        │  train.py train     ← YOLO11s，imgsz=1280，切片域
        ▼
best.pt
        │  train.py export    ← ONNX(FP32/static/opset12/simplify)
        │                       + model_meta.json（尺度链 + grid_signature
        │                       + min_object_mm + mm_per_px）
        ▼
deploy/（best.onnx + model_meta.json，必须同目录拷贝）
        │  detect.py          ← 工控机：16 切片串行 + 2 核 confinement + NMS
        │                       + mm 口径门控（丢弃 < min_object_mm 的框）
        ▼
JSON / 存图 / 预览
```

`detect_test.py` 与 `detect.py` 共用同一套切片/NMS/门控代码路径，只是不锁核、
可多进程、可出 HTML 报告、可做 `--compare`（2 核 vs 全速逐框 A/B 比对）。

## 4. 切片档位与尺度链（本方案的核心）

### 4.1 为什么整帧直送不可行

mm/px=0.8 时，5mm = 原生 **6.25px**。整帧 1920×1080 letterbox 到 1280，
scale = 1280/1920 = 0.667，5mm → **4.17px**。YOLO P3 头 stride=8，
经验检测下限约 8px（模型输入空间）。4.17px 远低于下限 → **整帧直送不可检**。

### 4.2 切片档位：640×360 → 1280

切片 640×360 letterbox 到 1280，scale = 1280/640 = **2.0**，
5mm → 6.25 × 2.0 = **12.5px**，高于 8px 下限、且在 30% 余量线（10.4px）之上。

切片网格（overlap 0.2）：

- xs = [0, 512, 1024, 1280]，ys = [0, 288, 576, 720] → **16 片**，每片 640×360。
- 重叠保证跨片边界的异物至少被一片完整包含（避免"半片漏检"）。

### 4.3 尺度链速查表（mm/px=0.8）

| 物理尺寸 | 原生 px | 切片模型 px | 判定 |
|---|---|---|---|
| 5.0mm（业务口径） | 6.25 | **12.5** | 良好（>10.4 余量线） |
| 4.16mm | 5.2 | 10.4 | 余量线（30% margin） |
| 4.0mm（训练截断） | 5.0 | 10.0 | 可检（>8 下限，<10.4 余量线） |
| 3.2mm | 4.0 | 8.0 | **物理下限**（=stride 8） |
| <3.2mm | <4.0 | <8.0 | 本档位不可检 |

### 4.4 档位上限与降级档

本档位（5mm 口径）要求 mm/px ≤ 5×2/8 = **1.25**；若训练截断取 4mm，则上限 4×2/8 = 1.0。
**mm/px 必须实测**（默认 0.8 只是估计值）：用 `detect.py --calibrate --ref-mm --ref-px`
在真实帧上测，参照物放在**上盖表面**（异物停留的那个平面），中心 + 四角各测一次，
记录极差。实测 mm/px 超过上限时，换更小切片档：

- **480×270 档**：scale = 1280/480 = 2.667，物理下限 8×0.8/2.667 = **2.4mm**，
  余量线 3.12mm，5mm 口径上限 mm/px ≤ 1.67。切片数会变多（推理变慢），仅在必要时启用。

## 5. 尺寸阈值体系（三个阈值，不能混）

| 阈值 | 参数位置 | 建议值 | 语义 |
|---|---|---|---|
| 物理检测下限 | 架构（stride 8） | **3.2mm** | 本档位能"看见"的最小值，写更小是谎言 |
| 训练/标注截断 | `prepare --min-mm` | **4.0mm** | 标注与训练正样本的下限，"有利于训练"的最小值 |
| 业务门控 | `export --min-mm` → meta → detect 丢弃 | **5.0mm** | 对外承诺口径，小于它的框在推理侧被丢弃 |

### 5.1 为什么训练截断取 4mm 而不是 5mm

把训练正样本下限放到业务门控**之下约一个回归噪声 σ**（4mm ≈ 原生 5px / 模型 10px；
框回归误差 ±1~2 原生像素 ≈ ±0.4~0.8mm，即该尺寸自身的 10~20%），
可以让"标签悬崖"远离业务阈值：

- 4–5mm 成为**训练缓冲带**：这些样本在训练里是正样本、在推理侧被门控丢弃。
  好处是 5mm 边界处的置信度干净——若截断正好取 5mm，则 4.9mm 是隐式负样本、
  5.1mm 是正样本，模型看到几乎相同的外观却拿到相反标签，边界梯度冲突，
  恰好在业务最关心的阈值处召回变差。
- 缓冲带让正类边界落在 4mm，5mm 位于一致正带内部 → **5mm 处召回更稳**。

### 5.2 为什么不能再低（<4mm 有害）

- 3.2–4mm = 模型 8–10px（原生 4–5px）：标注一致性 ±1 原生像素 = ±0.8mm = 20–25%，
  且与粉尘/水渍斑点混淆，标签噪声教出假阳性；训练容量被浪费在不可稳定学习的尺寸上。
- 污染 eval GT：`train.py eval` 的 GT 来自 dataset_full 标签，截断过低会把
  不可检尺寸塞进 GT，召回数字失真。

### 5.3 eval 口径的保守性（重要提醒）

训练截断(4mm) < 业务门控(5mm) 时，`train.py eval` 的 GT 包含 4–5mm 目标，
而门控会**故意丢弃**它们 → 报告的召回是**业务召回的保守下界**
（真实 ≥5mm 召回比报告值更高）。对外汇报时注明此口径；
若需业务口径数字，用 `--min-mm 5.0` 重跑 prepare 生成一份 GT-only 视图再 eval。

## 6. 物理标定（mm/px）

- **含义**：上盖表面平面上，1 像素对应多少毫米。所有 mm 口径换算都依赖它。
- **操作**：`detect.py --model deploy/best.onnx --calibrate --ref-mm <真实长度> --ref-px <像素长度>`。
  参照物（标定块/已知长度工件）放在**上盖表面**，中心 + 四角各测一次，取中位数写回配置，
  记录极差（极差大说明平面假设不成立或镜头畸变明显，需要换档或加畸变校正）。
- **平面假设**：本方案假设异物停留面近似平面。上盖若有明显弧面，四角极差会偏大，
  此时 mm/px 取"最不利角"的值（保守），或启用 480×270 档留余量。
- **建议加滞回带**：门控判定不要硬卡 5.0mm，建议 [4.8, 5.2] 滞回（现场可调），
  避免边界抖动导致同一异物时报时漏。

## 7. 模型与导出

- **模型**：YOLO11s（小模型）。不上 m/n：s 在 12.5px 目标上的召回/精度平衡最好，
  且 2 核 CPU 上 FP32 单片延迟可接受；m/n 收益边际、延迟翻倍。
- **导出**：FP32、静态 shape、opset 12、simplify。**不导出 half**（2 核 CPU 无 FP16 收益、
  精度风险）、**不导出 dynamic**（静态 shape 让 ORT 做最优图优化）、
  **ONNX 内不含 NMS**（NMS 在 detect.py Python 侧做，便于按 mm 口径后处理与滞回）。
- **训练超参（默认）**：epochs 300、batch 16、imgsz 1280、patience 60、
  conf 0.25 / iou 0.55 / max-det 200（推理侧）。召回优先：conf 取低、靠门控与 NMS 收拾。
- **为什么 ONNX-only 就够**：现场无 GPU、不允许装 OpenVINO/INT8 栈；
  FP32 ONNX + ORT CPU EP 在 2 核上单片延迟可接受（16 片串行，见 §8）。
  INT8 量化会损伤 8–12px 小目标召回，本项目**不做量化**。

## 8. 推理与部署架构（工控机侧）

- **16 切片串行**：逐片推理 + Python 侧 NMS + 跨片去重 + mm 门控。
  串行峰值内存约 **19.7MB/片**（单片 buffer），对比"16 片 batch 并行"峰值约 314MB，
  串行是 4GB 内存约束下的唯一选择；且串行让 CPU 占用平稳、可被 nice/优先级压制。
- **2 核 confinement（四层）**：
  1. 进程亲和性 `--cores 0,1`（默认 "0,1"，绑定到指定核心；填 `all` 则不绑定）+ 优先级 BELOW_NORMAL / `nice`（`--no-nice` 可关，仅调试用）；
  2. ORT `intra_op=2 / inter_op=1 / EXEC_SEQUENTIAL`（`--threads` 覆盖 intra）；
  3. cv2 `setNumThreads(1)`，避免 cv2 线程 × ORT 线程超订；
  4. BLAS 线程 env（OMP/MKL 等）同步限制，且须在 `import numpy` **之前**用 `setdefault` 落好。
- **节拍 `--takt-ms`**（默认 30000 ms）不是 confinement 手段：脚本处理完不 sleep，只在汇总时打印「P99 延迟 vs 预算 → 满足/超预算」，用来判定能否上线（换电站单次换电 3~5 min，单帧 30 s 内都可接受）。
- **grid_signature 交叉验证**：`model_meta.json` 的签名形如
  `0e3d61478710eb83|1920x1080|640x360|ov0.20,0.20|in1280|n16|xs=0,512,1024,1280|ys=0,288,576,720|sizes=640x360|scales=2.0000`。
  detect.py 本地重算后逐字段比对，不一致 exit 2（`--allow-grid-mismatch` 仅调试）。
- **签名不一致的常见原因**：拷错 ONNX/meta 版本、改了切片参数没重 export、
  相机分辨率变了（1920×1080 → 其它）。排查见《部署与操作手册.md》。

## 9. ROI / 两阶段分析（要不要加 ROI）

**结论：现阶段不加 ROI 裁剪，用"静态掩膜"代替；ROI 作为二期可选。**

- **为什么不做"检测→裁剪→再检测"两阶段**：级联会把一阶段的漏检放大成最终漏检，
  且 2 核上两次推理延迟翻倍，收益（少算背景）在 16 片串行下并不成立。
- **静态掩膜优先**：上盖表面区域是固定几何（相机固定、工件定位重复），
  用一张静态多边形掩膜在 NMS 后过滤框中心即可，零推理成本、零级联风险。
  掩膜用例：夹具/边框/已知非表面区域（`fixture_frame`）、上盖顶面（`pack_top`，
  若业务确认顶面不算"表面异物"）。
- **二期 ROI 的触发条件**：实测背景误报率高到影响节拍，或业务新增"只看某子区域"
  需求。届时 ROI 用**实例级多边形**（每个上盖型号一张），不做检测级联。

## 10. 验收方案

- **端到端指标**：`train.py eval` 在全帧集上算 P / R / F1 / mAP50 @IoU0.5，
  **召回优先**：内部判定"召回 ≥0.90 且 P ≥0.70"为基本可用；业务对外口径召回 ≥80%。
  （eval GT 含 4–5mm 缓冲带，报告召回为保守下界，见 §5.3。）
- **阶梯标定块验收**：现场用 3.2 / 4.0 / 5.0 / 6.0mm 阶梯块各拍 N 次，
  统计每档召回，确认 5mm 档 ≥ 业务目标、3.2mm 档"可见但不承诺"。
- **A-B 比对**：`detect_test.py --compare` 跑同一批图，2 核 confinement vs 全速，
  逐框比对（IoU 匹配 + 尺寸差），确认 confinement 不改变检测结果（只改变延迟）。
- **现场延迟验收**：记录单帧端到端延迟与 `--takt-ms` 节拍余量，确认不影响同机服务。

## 11. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| mm/px 未实测/测错 | 全口径失真，静默漏检 | 强制标定流程 + 四角极差记录 + 签名验证 |
| 尺度链错配（拷错版本） | 静默漏检 | grid_signature 逐字段比对，exit 2 |
| 弧面/畸变破坏平面假设 | 边缘区域 mm 失真 | 取最不利角 mm/px / 换 480×270 档 |
| 4–5mm 缓冲带污染对外召回数字 | 汇报口径争议 | 注明保守下界 / GT-only 视图重 eval |
| 2 核 confinement 拖慢延迟 | 现场 P99 超节拍预算 | 预算宽松（单次换电 3~5 min，30 s 内可上线）；关 --tta / 必要时 --cores 放开到更多核，勿降 imgsz 或改切片（会伤 5mm 目标） |
| 背景误报（夹具/边框） | 误报率高 | 静态掩膜（§9），二期实例级 ROI |
| 量化/半精度诱惑 | 小目标召回损伤 | 明确不做量化、不导出 half（§7） |
