# 部署与操作手册 —— battery_fod_lite

> 读者：训练操作员 / 现场集成工程师。所有命令均在 `battery_fod_lite/` 目录下执行。
> 设计理由见《技术方案.md》，标注口径见《标注规范.md》。

## 1. 环境

| 机器 | 依赖 | 说明 |
|---|---|---|
| 训练机（有 GPU） | `pip install ultralytics>=8.3.0 onnx opencv-python numpy` | train.py 全部子命令 |
| 工控机（2 核 CPU） | `pip install onnxruntime opencv-python numpy` | 只跑 detect.py |
| 开发机（全速测试） | 同工控机 | 只跑 detect_test.py，**禁止上工控机** |

Python ≥3.8（训练机建议 3.10+）。工控机若为 Windows，控制台代码页无关紧要，
脚本内部已强制 UTF-8 输出。

## 2. 训练机：四步走

```bash
# 0) 标定（先做！拿实测 mm/px，见 §3）

# 1) 数据准备：统一分辨率 → 清洗 → 切片
python train.py prepare --src D:/data/raw \
    --mm-per-px 0.80 --min-mm 4.0 \
    --remap 1:0 --ratios 0.8 0.1 0.1 --keep-empty-ratio 0.15
#    产出: dataset_full/（全帧，eval 用） dataset_sliced/（切片，训练用）

# 2) 训练（切片域 imgsz=1280）
python train.py train --epochs 300 --batch 16 --device 0 --patience 60

# 3) 导出 ONNX + meta（★ 业务门控写 5.0，与 prepare 的 4.0 不同，见技术方案 §5）
python train.py export --mm-per-px 0.80 --min-mm 5.0 --out deploy

# 4) 端到端验收（整帧 P/R/mAP50；报告召回为保守下界，见技术方案 §5.3）
python train.py eval
```

常用可选参数：

- `prepare --from-stage 2`：只重跑清洗+切片（改了 --min-mm 时用）。
- `prepare --force`：阶段 1 强制重新缩放已存在的图。
- `train --resume runs/<name>/weights/last.pt`：断点续训。
- `export --no-simplify / --dynamic / --half`：**默认都不要开**（技术方案 §7）。
- 一条龙：`python train.py all --src D:/data/raw --mm-per-px 0.80 --min-mm 4.0`。

## 3. 标定 mm/px（上线前必做）

1. 拍一张含**已知长度参照物**的现场帧（参照物平放在上盖表面，如 500mm 标定块）。
2. 用看图工具量出参照物的像素长度（如 625px）。
3. 运行：

   ```bash
   python detect.py --model deploy/best.onnx --calibrate \
       --image frame.jpg --ref-mm 500 --ref-px 625
   ```

   输出实测 mm/px（本例 0.8000）与档位建议（本档位 5mm 口径上限 1.25）。
4. **在中心 + 四角各测一次**，记录 5 个值：取中位数写回 `--mm-per-px`；
   极差 >3% 说明平面假设/畸变有问题，按《技术方案.md》§6 处理（取最不利角或换档）。
5. 把实测值填进 §2 的 prepare/train/export 三条命令（三处必须一致）。

---

## 4. 工控机上线

1. 拷贝 **整个 `deploy/` 目录**（`best.onnx` + `model_meta.json` 必须同目录）。
2. 自检（不推理，只校验尺度链与签名）：

   ```bash
   python detect.py --model deploy/best.onnx --selftest
   ```

3. 单张 / 批量：

   ```bash
   python detect.py --model deploy/best.onnx --image frame.jpg --save-img --out out/
   python detect.py --model deploy/best.onnx --dir D:/imgs --json res.json \
       --cores 0,1 --takt-ms 30000
   ```

   - `--cores 0,1`：绑定到哪两核（默认 0,1；避开其它服务占用的核）。填 `all` 表示不绑定，放开全部核（仅用于训练机上全速验收）。
   - `--takt-ms`：节拍预算 ms（默认 30000），**仅用于汇总时判定**——脚本处理完不 sleep，只在末尾打印「P99 延迟 vs 预算」告诉你能否上线，不占节拍。
   - `--no-nice`：不降优先级（**仅调试**，现场不要加）。
   - `--tta`：水平翻转 TTA，召回 +0.5~1.5pt，耗时 ×2（节拍允许时开）。
4. 结果：`--json` 输出每帧 bbox/score/size_mm/w_px/h_px；`--save-img` 出画框图。

### 上线 checklist

- [ ] deploy/ 整目录拷贝（onnx + meta 同目录、同一次 export 产出）。
- [ ] `--selftest` 通过（签名校验绿）。
- [ ] §3 标定完成，实测 mm/px 已写入 export 并重新导出。
- [ ] 阶梯块验收：3.2/4.0/5.0/6.0mm 各拍 ≥10 次，5mm 档召回 ≥ 业务目标。
- [ ] 20 帧现场图 `--limit 20` 实测单帧延迟，节拍余量确认。
- [ ] 任务管理器确认 CPU 只占 2 核、内存峰值 <500MB。
- [ ] 与同机其它服务并发跑 1 小时，无节拍互相击穿。

## 5. 开发机：detect_test.py（快速看效果）

```bash
# 流式逐张看 + 弹窗浏览（q/ESC 停止）
python detect_test.py --model deploy/best.onnx --dir D:/imgs --show

# 多进程全速 + 单文件 HTML 报告（可排序/筛选/缩略图）
python detect_test.py --model deploy/best.onnx --dir D:/imgs \
    --workers 8 --report report.html

# A/B 比对：2 核 detect.py vs 全速 detect_test.py，逐框 diff
python detect_test.py --model deploy/best.onnx --dir D:/imgs --compare
#    一致 → exit 0 打 ✅；有差异 → exit 3 并给排查方向
```

- `--workers N`：多进程跑多张图（自动按核数分线程，避免超订）。
- `--parallel`：ORT 图级并行；`--no-spin`：关自旋等待；`--inter N`：inter_op 线程。
- 横幅与 HTML 报告都有红字提醒：**本机数字不代表工控机**。

## 6. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动即 exit 2，打印两条签名 | ONNX 与 meta 不是一次 export / 切片参数改过没重导出 / 相机分辨率变了 | 重跑 `train.py export`，整目录重拷；`--allow-grid-mismatch` 仅调试 |
| 找不到 model_meta.json | 只拷了 onnx | 整目录拷贝 deploy/ |
| 检出全为空但肉眼有异物 | mm/px 填错（尺度链失真）或 conf 过高 | 重做 §3 标定；`--conf 0.15` 试探 |
| 边缘漏检、中心正常 | 签名不一致被放行过 / 切片网格分叉 | 看启动日志签名校验；重导出 |
| 延迟突然翻倍 | 其它服务抢核 / --cores 指到繁忙核 | 换核；查任务管理器 |
| 控制台乱码 | 老 Windows 代码页 | 脚本已内置 UTF-8 兜底；仍乱码则 `set PYTHONIOENCODING=utf-8` |
| 某张图读不了 | 文件损坏/非支持格式 | 日志标 `unreadable`，不中断整批 |

## 7. FAQ

- **为什么 16 片串行而不 batch？** 静态 batch=1 的 ONNX 无法 batch；且 16 片 batch
  峰值 ~314MB，4GB 工控机吃不消；串行峰值 ~19.7MB/片。
- **为什么 ONNX 里没有 NMS？** NMS 放在 detect.py Python 侧，才能按 mm 口径做门控/滞回。
- **为什么 FP32 不量化？** INT8/FP16 会损伤 8–12px 小目标召回；本项目精度优先。
- **业务以后要检 <3.2mm 怎么办？** 换 480×270 切片档：
  `prepare --slice-width 480 --slice-height 270 ...` → `train` → `export`（同参数），
  meta 签名自动更新，detect.py 读 meta 自适应；该档物理下限 2.4mm、推理更慢。
- **detect_test.py 能上工控机吗？** 不能。它不锁核、吃满 CPU，正是 detect.py 要避免的事。

# 附录 A：train.py 完整 CLI 参考

用法总形：`python train.py <子命令> [参数]`。子命令：`prepare / train / export / eval / all`。
不带子命令运行会打印帮助和"最常用第一条命令"提示。

## A.0 公共参数（prepare / train / export / all 都有）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--target-size W H` | `1920 1080` | 部署域分辨率（阶段 1 统一到的尺寸） |
| `--slice-width` | `640` | 切片宽（精度优先档，放大 2.0x） |
| `--slice-height` | `360` | 切片高 |
| `--overlap` | `0.2` | 切片重叠率（宽/高同值） |
| `--mm-per-px` | `0.8` | ★ 物理标定值，**必须实测替换**（§3） |
| `--min-mm` | `5.0` | 尺寸口径。prepare 用作标注/训练截断（建议传 4.0）；export 用作业务门控（保持 5.0） |

## A.1 `prepare` —— 数据准备（统一 → 清洗 → 切片）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--src` | 无（必填） | 原始标注目录（images/ + labels/，YOLO txt） |
| `--work` | `./work` | 中间产物目录 |
| `--dst-full` | `./dataset_full` | 全帧数据集（eval 用） |
| `--dst-sliced` | `./dataset_sliced` | 切片数据集（训练用，data.yaml 指向它） |
| `--remap` | `1:0` | 类别映射（标注工具的 label=1 → 0），可多条 |
| `--ratios` | `0.8 0.1 0.1` | train/val/test 切分比例 |
| `--seed` | `42` | 切分随机种子 |
| `--min-visibility` | `0.3` | 目标与切片的交并比低于此值时，丢弃该切片内的这个目标 |
| `--keep-empty-ratio` | `0.15` | 切片阶段保留纯背景切片的比例（抑制灰尘误检的关键，别设 0） |
| `--no-min-mm-filter` | 关 | 关掉按 `--min-mm` 清洗小框（默认开着） |
| `--from-stage` | `1` | 从第几阶段重跑（1 统一 / 2 清洗 / 3 切片） |
| `--force` | 关 | 阶段 1 强制重新缩放已存在的图 |

示例：`python train.py prepare --src D:/raw --mm-per-px 0.80 --min-mm 4.0`

## A.2 `train` —— 训练（切片域 imgsz=1280）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--data` | `data.yaml` | 数据集描述文件 |
| `--model` | `yolo11s.pt` | 预训练权重 |
| `--epochs` | `300` | 训练轮数 |
| `--batch` | `16` | 批大小（24G 显存可到 32） |
| `--imgsz` | `1280` | ★ 必须与 export 一致 |
| `--device` | `0` | GPU 序号；CPU 训练填 `cpu`（不推荐） |
| `--workers` | `8` | dataloader 进程数 |
| `--patience` | `60` | 早停轮数 |
| `--name` | `yolo11s_slice640x360_v1` | run 名（决定 weights 路径） |
| `--exist-ok` | 关 | 覆盖同名 run 目录 |
| `--resume` | 无 | 断点续训的 last.pt 路径 |
| `--cache` | 关 | 内存充足时缓存图片加速 IO |
| `--seed` | `42` | 训练随机种子 |
| `--override` | 空 | 追加/覆盖 Ultralytics 训练超参，如 `--override cos_lr=True` |

示例：`python train.py train --epochs 300 --batch 16 --device 0`

## A.3 `export` —— 导出 ONNX + model_meta.json

| 参数 | 默认 | 说明 |
|---|---|---|
| `--weights` | `runs/yolo11s_slice640x360_v1/weights/best.pt` | 训练产物 |
| `--out` | `./deploy` | 输出目录（整目录拷到工控机） |
| `--imgsz` | `1280` | ★ 必须与训练一致 |
| `--opset` | `12` | ONNX opset（12 兼容性最好） |
| `--simplify` / `--no-simplify` | 开 | 图简化（保持默认开） |
| `--dynamic` | 关 | 动态 shape（CPU 上更慢，**不要开**） |
| `--half` | 关 | FP16（CPU 上不建议，**不要开**） |
| `--conf` | `0.25` | 写入 meta 的默认置信度阈值 |
| `--iou` | `0.55` | 写入 meta 的默认 NMS IoU 阈值 |
| `--max-det` | `200` | 单帧最多保留框数 |
| `--model-tag` | `yolo11s` | 写进 meta 的模型标识 |

示例：`python train.py export --mm-per-px 0.80 --min-mm 5.0 --out deploy`
（export 会打印尺度链：`5.0mm → 原生 6.25px → 2.00x → 模型 12.50px`，并校验是否低于 8px 下限。）

## A.4 `eval` —— 端到端验收（整帧 P/R/F1/mAP50）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--model` | `deploy/best.onnx` | 待验收 ONNX |
| `--images` | `dataset_full/images/test` | 整帧测试图目录 |
| `--labels` | `dataset_full/labels/test` | 对应标签目录 |
| `--conf` | `0.25` | 置信度阈值 |
| `--iou` | `0.55` | NMS IoU 阈值 |
| `--mm-per-px` | 无（取 meta） | 覆盖 meta 标定值（仅排查用） |

示例：`python train.py eval`（报告召回为保守下界，见《技术方案.md》§5.3）

## A.5 `all` —— 一条龙（prepare → train → export）

参数为 A.1+A.2+A.3 的并集（不含 `--weights`，自动接训练产物）。
示例：`python train.py all --src D:/raw --mm-per-px 0.80 --min-mm 4.0`
（注意：`all` 里 `--min-mm` 同时作用于 prepare 与 export；若要走"训练截断 4.0 / 门控 5.0"
的推荐配置，请分开跑 prepare 与 export，分别传值。）

# 附录 B：detect.py 完整 CLI 参考（工控机）

用法：`python detect.py --model <best.onnx> [--image ... | --dir ...] [参数]`。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--model` | 无（必填） | best.onnx 路径（同目录需有 model_meta.json） |
| `--image` | 无 | 单张或多张图片路径（可多个） |
| `--dir` | 无 | 批量目录（递归） |
| `--out` | 无 | 输出目录（配合 --save-img / --json） |
| `--json` | 无 | 结果 JSON 输出路径 |
| `--save-img` | 关 | 同时输出画框图 |
| `--preview-side` | `0` | 画框图最长边限制（0=原尺寸） |
| `--limit` | `0` | 最多处理 N 张（0=全部） |
| `--warmup` | `1` | 预热帧数（不计入延迟统计） |
| `--conf` | 无（取 meta） | 置信度阈值覆盖 |
| `--iou` | 无（取 meta） | NMS IoU 阈值覆盖 |
| `--max-det` | 无（取 meta） | 单帧最多保留框数覆盖 |
| `--mm-per-px` | 无（取 meta） | 标定值覆盖（仅排查用） |
| `--tta` | 关 | 水平翻转 TTA（召回 +0.5~1.5pt，耗时 ×2） |
| `--cores` | `0,1` | 绑定到哪两核（进程亲和性）；填 `all` 表示不绑定，放开全部核 |
| `--threads` | 无（=2） | ORT intra_op 线程数（confinement 默认 2；也读环境变量 FOD_THREADS） |
| `--no-nice` | 关 | 不降进程优先级（**仅调试**） |
| `--takt-ms` | `30000` | 节拍预算 ms，**仅用于汇总时判定**（末尾打印 P99 vs 预算），不 sleep、不占节拍 |
| `--allow-grid-mismatch` | 关 | 签名不一致时降级为 WARN 继续（**仅调试**） |
| `--quiet` | 关 | 不逐张打印 |
| `--selftest` | 关 | 不推理，只校验尺度链/切片网格/签名 |
| `--calibrate` | 关 | 实测 mm/px 并给档位建议（配 --image/--ref-mm/--ref-px） |
| `--ref-mm` | 无 | 标定参照物真实长度 mm |
| `--ref-px` | 无 | 标定参照物像素长度 px |

**退出码**：`0` 正常；`1` 致命错误（缺 model/meta、无输入图等）；`2` grid_signature
不一致（训练尺度 ≠ 推理尺度，拒绝运行）。

示例：

```bash
python detect.py --model deploy/best.onnx --selftest
python detect.py --model deploy/best.onnx --calibrate --image f.jpg --ref-mm 500 --ref-px 625
python detect.py --model deploy/best.onnx --image f.jpg --save-img --out out/
python detect.py --model deploy/best.onnx --dir D:/imgs --json r.json --cores 0,1 --takt-ms 30000
```

# 附录 C：detect_test.py 完整 CLI 参考（开发机，禁上工控机）

输入/输出/阈值类参数与 detect.py 完全相同（`--model --image --dir --out --json
--save-img --preview-side --limit --warmup --conf --iou --max-det --mm-per-px --tta
--allow-grid-mismatch --quiet --selftest --calibrate --ref-mm --ref-px`），此处只列差异与新增。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--report` | 无 | 生成单文件 HTML 报告（自动开启 --save-img） |
| `--show` | 关 | 每张弹窗显示（强制单进程；q/ESC 停止） |
| `--show-pause` | 关 | 弹窗模式下每张暂停等按键 |
| `--threads` | 无（=全核） | ORT intra_op 线程数（不锁核，默认吃满） |
| `--workers` | `0`（自动） | 多进程数；自动 = min(核/2, 8, 图数)，单图强制 1 |
| `--parallel` | 关 | ORT 图级并行（ORT_PARALLEL） |
| `--inter` | `1` | ORT inter_op 线程数 |
| `--no-spin` | 关 | 关闭 ORT 线程自旋等待（默认开着换低延迟） |
| `--compare` | 关 | A/B 比对：子进程跑 2 核 detect.py，与本脚本全速结果逐框 diff |
| `--compare-cores` | `0,1` | 比对时 detect.py 绑定的核 |
| `--compare-threads` | `2` | 比对时 detect.py 的 intra 线程数 |
| `--takt-ms` | `30000` | 节拍预算 ms，仅用于汇总判定 P99（同 detect.py；全速数字不代表工控机，一般用不到） |

**退出码**：`0` 正常（`--compare` 时=两边逐框一致）；`1` 致命错误；`2` 签名不一致；
`3` = `--compare` 发现差异（附排查方向）。

示例：

```bash
python detect_test.py --model deploy/best.onnx --dir D:/imgs --show
python detect_test.py --model deploy/best.onnx --dir D:/imgs --workers 8 --report r.html
python detect_test.py --model deploy/best.onnx --dir D:/imgs --compare
```
